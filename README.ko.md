# 라이젠 5000시리즈(5900X), 24시간 무중단 시스템(홈서버·Proxmox·NAS)에서 유휴 상태일 때 랜덤 종료/재부팅되는 문제

> **주의:** 아래 내용은 오실로스코프나 실제 전기적 측정으로 증명된 게 아닙니다. 전부 BIOS 설정, 소프트웨어 센서 로깅, 무크래시 가동시간을 근거로 추론한 내용입니다. 이 방법이 여러분 시스템에서는 안 통할 수도 있습니다. 저는 이걸로 해결됐습니다.

## 증상

라이젠 5000시리즈 CPU(5900X + ASUS ROG Strix X570-E Gaming 조합에서 실제로 재현. 커뮤니티 보고를 보면 라이젠 2000~9000시리즈, AM4~AM5 전반에 걸쳐, 제조사·보드 종류와 상관없이 나타나는 것으로 보임)에서 **유휴 상태이거나 로드가 낮을 때만** 랜덤하게 꺼지거나 재부팅됩니다. 부하가 많이 걸릴 때는 절대 안 그럽니다. 과열도 아니고, OS 로그에도 미리 특별한 에러가 안 남는 경우가 많습니다. 하드웨어 워치독을 켜뒀다면 그냥 워치독 리셋만 찍히고 원인 설명이 없을 수도 있습니다. MCE(Machine Check Exception)가 잡히는 경우, 보통 코어 내부 뱅크로 디코딩되고 메모리 주소는 안 잡힙니다(`ADDRV=0`) — 겉보기엔 메모리 문제처럼 보여도 실제 램(DIMM) 결함은 아니라는 뜻입니다.

게임하거나 인터넷 하는 용도로 거의 유휴 상태로 안 두는 데스크탑에서는 잘 안 보일 수 있는데, 홈서버나 하이퍼바이저 호스트, NAS처럼 오랫동안 유휴 상태로 무인 운영되는 시스템에서는 계속 터집니다.

## 아닌 것으로 확인된 것들

같은 문제를 쫓고 계신다면 참고하세요. 직접 테스트해서 배제한 항목들입니다:
- **램** — memtest 여러 패스 다 클린했습니다.
- **특정 코어 하나의 결함** — MCE가 한 번 잡혔을 때 관련 물리 코어 하나를 격리·비활성화해봤지만, 그 이후로도 크래시가 여러 번 더 발생했고 MCE는 한 번도 재발하지 않았습니다. "특정 코어가 문제다"라고 단정하기 전에 증거부터 더 모으세요 — 거의 헛다리일 가능성이 높습니다.
- **메인보드나 파워** — 직접적인 증거는 양쪽 다 없지만, 아래 해결책은 하드웨어 고장이 아니라 CPU/VRM 펌웨어 설정 레벨에서 접근한 겁니다.

## 제 추론(가설)

제 추론으로는, 이게 흔히 "언더볼팅 실패"할 때 생각하는 "전압이 정적으로 너무 낮음" 문제가 아니라, **유휴 상태 전환 시점의 순간 전류/전압 처리 문제**로 보입니다. 즉 **일부러 전압을 건드린 적이 없어도 언더볼팅에 실패한 것처럼 똑같이 동작합니다** — 일부 보드의 기본(BIOS 디폴트) 유휴 전력 관리가, CPU가 깊은 유휴 상태에서 활성 상태로(혹은 반대로) 튈 때 발생하는 아주 짧은 순간의 전류 스파이크에 VRM이 충분한 여유를 못 주도록 설정돼 있는 것 같습니다.

제가 보기엔 이건 하드웨어 결함이라기보단 BIOS/펌웨어 레벨의 전류 제한 설정 문제(CPU의 "디지털 퓨즈"가 이 특정 순간 전류에 비해 너무 보수적으로 잡혀있는 것)로 보입니다. 다만 솔직히 말씀드리면, 이 마이크로초 단위의 실제 VRM 순간 전압 강하는 소프트웨어 센서 폴링으로는 절대 직접 관측이 안 됩니다(아무리 빠르게 폴링해도 초당 1회 정도밖에 안 됨). 그래서 이건 "먹힌 해결책"에서 역추론한 강한 정황 증거이지, 완전히 증명된 근본 원인은 아니라는 점 미리 말씀드립니다.

## 안 먹혔던 것들

- Global C-state를 끄고 "Power Supply Idle Control"을 덜 공격적인 유휴 모드로 바꾸는 것만으로는 크래시가 안 멈췄습니다.
- **VDDCR CPU Offset**(전압 커브 전체를 평행이동)을 양의 방향으로 줘봤는데, 실제 유휴 전압 바닥은 거의 안 움직였고(로그 기준 0.02V도 안 움직임), 반대로 부스트 클럭 시 전압 천장은 AMD가 이 세대 CPU에 대해 공식 문서화한 하드캡(~1.55V)을 훌쩍 넘겨버렸습니다 — 실제 문제는 안 고치면서 위험만 새로 만든 셈입니다. 보드에 Offset 모드와 Fixed/Manual 모드가 따로 있다면 둘이 완전히 다르게 동작한다는 걸 알아두세요 — 유휴 바닥과 부스트 천장은 "커브 전체를 그대로 평행이동"하듯 함께 움직이지 않습니다.

## 지금까지 먹힌 것

BIOS의 CPU/PBO 관련 섹션에서 아래를 전부 같이 적용했습니다(메뉴 이름은 제조사마다 조금씩 다를 수 있음):
1. **Precision Boost Overdrive(PBO): Manual**로 (Auto 말고)
2. **EDC(Electrical Design Current, 순간 전류 제한) 상한: 올림** — 이게 핵심입니다. 기본값 EDC 제한이 이 세대 CPU의 전력 상태 전환 시 실제 순간 전류 요구량에 비해 너무 작게 잡혀있는 것으로 보입니다. 유의미하게 올려야 합니다(제 경우 기본값의 2배).
3. **PPT(총 전력) 제한**: 쿨링이 감당할 수 있는 수준까지 올림
4. **플랫폼/CPU 온도 스로틀 제한**: 수동으로, CPU 실제 온도 한계보다 여유 있게 설정
5. 보조로 **VDDCR CPU Offset**을 작게(+0.1V 정도) — 위 조치들에 얹는 보조 수단이지 주력 해결책은 아닙니다.

사용한 쿨링: 듀얼타워 공랭(딥쿨 AK 시리즈로 추정). 위 PPT/온도 제한 수치는 이 정도 급 이상의 쿨링을 전제로 한 값이니, 쿨러가 더 작다면 수치 자체보다는 "이런 설정이 존재한다"는 방향성만 참고하세요.

**출처를 밝히자면:** EDC/PPT/PBO Manual이라는 방향 자체는 제가 처음부터 생각해낸 게 아니라, 똑같은 CPU+메인보드 조합에서 같은 유휴크래시 증상을 이 방법으로 해결한 커뮤니티 스레드를 보고 알게 됐습니다. 제가 직접 한 건 이걸 제 시스템에 실제로 적용해보고, 제 쿨링/사용 환경에 맞게 EDC/PPT/온도/오프셋 수치를 튜닝하고, 적용 전후로 전압/온도를 직접 실측해서 검증하고, 이렇게 정리해서 남긴 것입니다.

지금까지 결과: 실측 전압 샘플링을 보면 유휴 전압 바닥이 안정적이고 건강한 범위에서 유지되고 있고, 이전 크래시 직전에 실측됐던 낮은 값(~0.86V) 쪽으로 다시 떨어지지 않고 있습니다. 이전 최장 무크래시 가동시간 기록을 이미 넘겼습니다.

**업데이트 — 확정:** 이제 200시간+(8일+) 연속 무크래시로 가동 중이며, 위에서 말한 "수백 시간" 관찰 기준을 넉넉히 넘겼습니다. 확정적으로 해결된 것으로 결론짓습니다.

## 결과를 공유하고 싶으시다면

이 방법을 시도해보셨다면 성공하셨든 실패하셨든 이 저장소에 issue나 discussion으로 남겨주세요 — 다른 CPU/보드/쿨링 조합, 다르게 잡은 EDC/PPT 수치 등 뭐든 좋습니다. 이런 종류의 문제는 여러 환경의 데이터가 쌓일수록 다 같이 도움이 되는 케이스예요.

## 직접 디버깅하신다면

- CPU 코어 전압/온도/부하를 계속 로그로 남기세요(플랫폼 센서 값을 1분 간격으로만 찍어도 충분합니다) — 다음 크래시 "직전" 데이터가 있어야지, 크래시 "후" 로그만 봐서는 못 잡습니다.
- MCE가 잡혔다면 뱅크 번호와 주소가 실제로 잡혔는지 확인하세요 — 주소가 안 잡히면 메모리 결함이 아닐 가능성이 높습니다.
- MCE 한 번 잡혔다고 바로 "특정 코어가 문제"라고 단정하지 마세요 — 격리해서 직접 테스트해보세요.
- 전압 오프셋부터 시도해보실 거라면, 적용 전/후로 실제 유휴 바닥값과 부스트 천장값을 직접 측정하세요 — 원하는 대로 됐다고 그냥 가정하지 마세요.
- 전압 커브 설정에 시간을 더 쓰기 전에, BIOS의 PBO/전류 제한(EDC/TDC/PPT) 쪽부터 먼저 보세요 — 이 특정 CPU/유휴크래시 패턴에서는 전압 커브가 아니라 전류 제한 쪽이 빠져있던 퍼즐 조각이었습니다.
