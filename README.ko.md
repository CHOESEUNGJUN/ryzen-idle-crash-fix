# 라이젠 5000시리즈(5900X) 유휴 랜덤 재부팅 — 24시간 돌리는 서버에서

## 1. 개요

24시간 켜두는 서버(홈서버, Proxmox, NAS)에서 라이젠 5000시리즈 CPU가 유휴 상태일 때만 랜덤하게 꺼지거나 재부팅되는 문제를 기록한다.[^1]

## 2. 증상

- 부하가 걸릴 때는 발생하지 않고, **유휴 상태이거나 로드가 낮을 때만** 랜덤하게 종료/재부팅됨.
- 과열 없음. 로그에 사전 경고 없음.
- 하드웨어 워치독을 사용 중이면 워치독 리셋만 기록되고 원인은 안 남는 경우가 많음.
- MCE(Machine Check Exception)가 잡히는 경우, 코어 내부 뱅크로 디코딩되고 메모리 주소는 잡히지 않음(`ADDRV=0`). 겉보기엔 메모리 문제처럼 보이나 실제 RAM 결함은 아님.
- 게이밍용 데스크탑처럼 거의 유휴 상태로 두지 않는 환경에서는 잘 드러나지 않고, 서버처럼 장시간 유휴 상태로 무인 운영되는 환경에서 지속적으로 발생함.

## 3. 배제된 원인

- **RAM**: memtest 다회 클린 확인.
- **특정 코어 결함**: MCE 발생 시점의 물리 코어를 격리·비활성화했으나 이후에도 크래시가 계속 발생했고, MCE는 재발하지 않음. 단발성 MCE로 코어 결함을 단정할 근거는 부족함.
- **메인보드/파워 결함**: 직접적인 증거 없음. 아래 해결 방법이 하드웨어 결함이 아닌 CPU/VRM 펌웨어 설정 수준에서 접근한 것이므로 별도 검증하지 않음.

## 4. 원인 분석

정적으로 전압이 낮은 문제가 아니라, **유휴↔활성 전환 시점의 순간 전류 스파이크**를 VRM이 감당하지 못하는 것으로 판단됨.[^2] 전압을 직접 건드리지 않아도 언더볼팅 실패와 동일한 양상을 보이는 이유가 여기 있음. 보드의 기본 BIOS 설정이 이 전환 구간의 순간 전류에 충분한 여유를 주지 않는 것으로 추정됨.

즉 원인은 전압 커브가 아니라 **전류 제한(EDC)** 설정으로 판단. 오실로스코프 등 직접적인 전기적 측정으로 확인된 것은 아니며, 조치 이후의 결과로부터 역으로 추론한 근거임.

## 5. 조치 내역

### 5.1 효과 없었던 조치

- Global C-state 비활성화 + Power Supply Idle Control을 Typical 모드로 변경 — 단독으로는 재발 방지 효과 없음.
- VDDCR CPU Offset을 양의 방향으로 조정 — 실측 결과 유휴 전압 바닥은 거의 변화 없었음(0.02V 미만). 반면 부스트 클럭 시 전압 상한이 AMD 공식 규격 상한(~1.55V)을 초과함. 문제 해결 없이 위험만 증가.

### 5.2 적용한 조치

BIOS CPU/PBO 항목에서 아래를 동시 적용:

1. Precision Boost Overdrive(PBO): **Manual** (Auto 아님)
2. EDC(Electrical Design Current) 상한: **상향** — 핵심 조치. 기본값이 해당 세대 CPU의 전환 구간 순간 전류 요구량 대비 낮게 설정된 것으로 판단하여 기본값의 약 2배로 상향.
3. PPT(총 전력) 상한: 쿨링 성능이 허용하는 범위 내에서 상향.
4. 플랫폼/CPU 온도 스로틀 한계: 수동 설정, 실제 열 한계 대비 여유 확보.
5. VDDCR CPU Offset +0.1V — 보조 조치, 주된 해결 요인은 아님.

사용 쿨링: 듀얼타워 공랭(딥쿨 AK 계열). 위 PPT/온도 수치는 해당 쿨링 성능을 전제로 하며, 쿨러 성능이 낮은 경우 수치보다 설정 항목의 존재 자체를 참고할 것.

해당 조치(EDC/PPT/PBO Manual)의 방향성은 동일 CPU·보드 조합에서 같은 증상을 겪은 커뮤니티 사례를 참고함. 본 문서의 기여는 실제 환경에 맞춘 수치 튜닝과 적용 전후 전압/온도 실측 검증임.

## 6. 결과

조치 적용 후 200시간 이상(8일 이상) 연속 무중단·무크래시 가동 확인. 전압 실측 결과 유휴 전압 바닥이 안정 범위에서 유지되며, 조치 이전 크래시 직전에 관측된 저전압 값(~0.86V) 재현 없음. 재발 방지 확정으로 판단함.

## 7. 참고 — 동일 증상 디버깅 시

- 전압·온도·부하를 상시 로깅할 것. 크래시 발생 이후가 아니라 발생 직전 데이터가 필요함.
- MCE 발생 시 뱅크 번호와 주소 캡처 여부를 확인할 것. 주소 미캡처는 메모리 결함 가능성이 낮음을 시사함.
- 단발성 MCE로 특정 코어 결함을 단정하지 말고 추가 검증할 것.
- 전압 오프셋을 우선 시도할 경우, 적용 전후의 유휴 바닥값과 부스트 상한값을 실측할 것.
- 전압 커브보다 BIOS의 PBO/전류 제한(EDC/TDC/PPT) 설정을 우선 검토할 것.

동일 증상을 겪고 있거나 다른 조합(CPU/보드/쿨링)에서 시도한 결과가 있다면 이슈로 남겨줄 것.

[^1]: 5900X + ASUS ROG Strix X570-E Gaming 조합에서 재현. 커뮤니티 보고에 따르면 라이젠 2000~9000시리즈, AM4~AM5 전반에 걸쳐 제조사·보드 종류와 무관하게 발생하는 것으로 보임.
[^2]: 마이크로초 단위의 VRM 순간 전압 강하는 소프트웨어 센서 폴링(초당 약 1회)으로 직접 관측이 불가능함. 따라서 본 원인 분석은 조치 결과로부터의 정황적 추론이며, 전기적 측정으로 검증된 근본 원인은 아님.
