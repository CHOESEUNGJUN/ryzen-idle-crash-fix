# 라이젠 5000시리즈(5900X) 유휴 랜덤 재부팅 — 24시간 돌리는 서버에서

24시간 켜두는 서버(홈서버, Proxmox, NAS)에서 라이젠 5000시리즈 CPU가 **유휴 상태일 때만** 랜덤하게 꺼지거나 재부팅되는 문제.[^1] 부하 걸릴 때는 절대 안 그런다. 과열도 아니고 로그에 사전 경고도 없다. 워치독 켜놨으면 그냥 워치독 리셋만 찍히고 끝.

MCE(Machine Check Exception) 잡히면 보통 코어 내부 뱅크로 뜨고 메모리 주소는 안 잡힘(`ADDRV=0`). 램 문제처럼 보이지만 아니다.

게이밍용 데스크탑은 거의 유휴로 안 두니까 잘 안 보이는데, 서버처럼 계속 놀려두는 용도로 쓰면 바로 터진다.

## 아니었던 것들

- **램**: memtest 여러 번 돌렸는데 다 클린.
- **코어 하나 불량**: MCE 한 번 잡혀서 그 코어 하나 격리해봤는데, 그러고도 크래시 계속 남. MCE는 그 뒤로 한 번도 재발 안 함. 한 번 잡혔다고 코어 탓하지 말 것.
- **보드/파워 불량**: 증거는 없음. 근데 아래 해결법이 하드웨어 레벨이 아니라 CPU/VRM 펌웨어 설정 레벨이라 딱히 볼 필요도 없었음.

## 왜 이러는지

전압이 정적으로 낮은 게 아니라, **유휴↔활성 전환 순간의 전류 스파이크**를 VRM이 못 받아주는 거로 보인다.[^2] 언더볼팅 한 적 없어도 언더볼팅 실패한 것처럼 똑같이 행동하는 이유가 이거다. 보드 기본 BIOS 세팅이 이 순간 전류 스파이크한테 여유를 안 주게 잡혀있는 듯.

전압을 억지로 올린다고 되는 문제가 아니라 **전류 제한(EDC)** 쪽이 원인이라는 게 요지. 오실로스코프로 찍은 건 아니고 "이렇게 바꿨더니 안 터짐"으로 역추론한 거라, 그 점은 감안하고 보자.

## 안 먹힌 것

- Global C-state 끄고 Power Supply Idle Control을 Typical로 바꾸는 것 — 이것만으로는 안 됨.
- VDDCR CPU Offset 양수 방향으로 주기 — 유휴 바닥 전압은 거의 안 움직이고(0.02V도 안 됨), 부스트 천장 전압만 AMD 공식 상한(~1.55V) 넘겨버림. 위험만 늘고 문제는 그대로.

## 먹힌 것

BIOS CPU/PBO 섹션에서 이거 다 같이:

1. PBO: **Auto 말고 Manual**
2. EDC 상한: **올림** — 이게 핵심. 기본값이 이 세대 CPU 전환 순간 전류 요구량보다 작게 잡혀있음. 기본값의 2배 정도로.
3. PPT: 쿨링 버티는 선까지 올림
4. 온도 스로틀 한계: 수동으로, 여유 있게
5. VDDCR Offset +0.1V — 이건 보조. 주력 아님.

쿨링은 듀얼타워 공랭(딥쿨 AK급). 저 PPT/온도 수치는 이 정도 쿨링 기준이니까, 쿨러 작으면 숫자보다 "이런 옵션이 있다"는 것만 참고.

EDC/PPT/PBO Manual 방향 자체는 커뮤니티에서 같은 조합(5900X + X570) 겪은 사람 글 보고 따라간 거고, 내가 한 건 내 시스템에 맞게 수치 튜닝하고 전후 전압/온도 직접 재서 검증한 것.

**결과: 확정.** 200시간+(8일+) 무크래시. 전압 실측해보면 유휴 바닥이 안정적으로 유지되고, 예전 크래시 직전에 찍혔던 ~0.86V 근처로 다시 안 떨어짐.

## 너도 겪고 있다면

댓글/이슈로 본인 조합(CPU/보드/쿨링) + 먹힌 EDC/PPT 수치 남겨주면 다른 사람들한테도 도움 됨.

## 직접 디버깅할 때 팁

- 전압/온도/부하 계속 로깅해둘 것 — 크래시 "후" 로그 말고 "직전" 데이터가 있어야 함.
- MCE 잡히면 뱅크 번호랑 주소 확인 — 주소 안 잡히면 메모리 결함 가능성 낮음.
- MCE 한 번 잡혔다고 코어 탓하지 말고 직접 테스트.
- 전압 오프셋 먼저 만질 거면 전후로 실제 바닥/천장 값 재볼 것 — 됐다고 그냥 믿지 말고.
- 전압 커브보다 EDC/TDC/PPT 전류 제한 쪽부터 볼 것. 이 증상은 전류 쪽이 빠진 퍼즐이었음.

[^1]: 5900X + ASUS ROG Strix X570-E Gaming 조합에서 재현. 커뮤니티 보고 보면 라이젠 2000~9000시리즈, AM4~AM5 전반, 제조사/보드 안 가리고 나타나는 걸로 보임.
[^2]: 이 마이크로초 단위 VRM 전압 강하는 소프트웨어 센서 폴링(초당 1회 수준)으로는 직접 못 잡음. 그래서 위 설명은 "먹힌 해결책"에서 역추론한 정황이지, 오실로스코프로 증명한 근본 원인은 아님.
